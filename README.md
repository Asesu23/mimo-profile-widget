# Mimo Profile Widget

A live SVG badge — streak, coins, and XP — for embedding your [Mimo](https://mimo.org) coding progress in a GitHub README, generated by an unofficial Next.js app deployed on Vercel.

```md
[![Mimo Stats](https://your-deployment.vercel.app/api/widget/<id>)](https://mimo.org)
```

## Why this exists

Mimo doesn't have a public API the way Duolingo does, so there's no way to pull streak/XP/coin data by username alone. This project authenticates the same way the official web app does, then re-exposes the result as a small, cacheable SVG endpoint that any README can embed.

## How it works

1. You sign in once through the form on the deployed site (email + password, sent once over HTTPS).
2. The server exchanges your credentials for a Firebase `idToken` and `refreshToken`. The password is discarded immediately after this single request — it is never logged or stored anywhere.
3. Only the `refreshToken` is persisted, and only after AES-256-GCM encryption at rest.
4. You get back a public URL (`/api/widget/<id>`) with no credentials or secrets in it — that's what goes in your README.
5. Each time that URL is fetched, the server decrypts the stored token, exchanges it for a fresh `idToken` (no password involved), pulls your stats, and renders the SVG. Responses are cached for 30 minutes to avoid hammering Mimo's API.
6. A **Disconnect** button on the site deletes the stored token permanently.

### Honest limitations

- Mimo's API is not public and not documented. It was reverse-engineered from the official web app's network traffic and may change or break without notice.
- This project is **not affiliated with, endorsed by, or supported by Mimo**. Use it at your own discretion — running it means trusting whoever operates the deployment (yourself, if you deploy your own instance) with a refresh token tied to your account.
- If you're deploying a public instance for other people to use, they are trusting your server with their Mimo session. Prefer self-hosting your own instance over using someone else's deployment with your real credentials.

## Tech stack

- **Next.js 14** (App Router, TypeScript) — form, API routes, SVG rendering
- **Upstash Redis** — encrypted token storage
- **Node's built-in `crypto`** — AES-256-GCM encryption at rest
- **Firebase Identity Platform** — the same auth backend Mimo's web app uses

## Setup

```bash
npm install
cp .env.example .env.local
```

Fill in `.env.local`:

- `WIDGET_ENCRYPTION_KEY` — generate with `openssl rand -base64 32`
- `KV_REST_API_URL` / `KV_REST_API_TOKEN` — added automatically to your Vercel project when you connect the "Upstash for Redis" integration (Storage → Marketplace Database Providers); pull them locally with `vercel env pull .env.local`

```bash
npm run dev
```

## Deploy

```bash
vercel deploy
```

Add an Upstash Redis database to the project from the Vercel dashboard (Storage → Marketplace Database Providers), then set `WIDGET_ENCRYPTION_KEY` as an environment variable before deploying to production.
